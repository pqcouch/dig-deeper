## Amendment G — Synoptic Mode: passages the canon tells twice

### Problem

The skill has three modes — Fresh Exegesis, Claim Audit, Macro-Synthesis — and **all three assume one passage standing in one place.** Multi-Passage Sweep Mode is explicitly "six or more passages **from the same book**", so it does not cover this either.

But Scripture repeatedly tells the same material twice, and when it does, **the second telling is the canon's own commentary on the first.** That is not a curiosity; it is one of the richest kinds of evidence available, and it is invisible to a run that works either passage alone. The Decalogue run put the point sharply: **four of its five headline findings could not have been reached from either passage on its own.** A dig on Exodus 20 alone cannot know that God commended the people's terror; a dig on Deuteronomy 5 alone cannot feel how much Exodus withheld.

Where this recurs, in this library and beyond:

| Pair | Direction of dependence | Status |
|---|---|---|
| **Exod 20:1–17 // Deut 5:1–33** | **Stated by the later text** (כַּאֲשֶׁר צִוְּךָ, 5:12, 16) | Done, 10 Sep 2026 |
| **Isa 36–39 // 2 Kgs 18–20** | **Open** — and already named in `SKILL.md` Phase 0.55 as the paradigm case | Not done; both books have material in the folder |
| **2 Sam 22 // Ps 18** | Open | Not done |
| **Ps 14 // Ps 53** | Open | Not done |
| **Obad 1–9 // Jer 49:7–22** | Open | Not done |
| **Samuel–Kings // Chronicles** | Chronicles later, and says so by omission rather than by formula | Not done |
| **The Synoptic Gospels** | Contested | Not done |
| **Exod 23:10–19 // Exod 34:11–26** | Within one book | Not done |

**The variable that governs everything is the second column.** Where the later text *states* its dependence, the two passages are an original and an authorised re-issue, and the differences are homiletic moves. Where the direction is *open*, the same differences are evidence in an unresolved question, and the run must — per the rule the skill already carries at Phase 0.55 — report both orders and resolve neither. **A mode that did not force that distinction at the start would produce confident nonsense on Isaiah 36–39.**

Three further things the Decalogue run had to invent, each of which will recur:

- **Phase 0.6 has to run twice**, once per passage, because each passage's positional necessity is a fact about its own book.
- **The Citation Triad runs with the source inside the same corpus.** Move 2 (book usage) and Move 4 (internal echo) nearly collapse into one operation when a book's "source" is its own five-volume work. Worth saying, so the run does not report the collapse as a nil return.
- **Two book-overviews are live, and they are rarely of equal maturity.** In this case one was finalised at v1.0.5 and corpus-era; the other was v0.1.0, ESV, and pre-corpus. The asymmetry is itself a finding, and there is currently no instruction to look for it.

### File and anchor

**Edit 1** — `SKILL.md`, `## Workflow`, the "Choose the mode first" paragraph. Replace:

> **Choose the mode first.** Fresh Exegesis (default — the full report, table below) or **Claim Audit Mode** (Phase 0.5b — testing named claims from an overview or a new source), or **Macro-Synthesis Mode** (Phase 0.5c — drawing together the cross-pericope arguments a completed set of dig-deeper runs jointly demonstrates). The decision rules are at the end of Phase 0.5b and Phase 0.5c. If the ask is "is this claim/overview/source right?", it's a claim audit; if it's "what do all these runs add up to / what wider arguments emerge across the book?", it's a macro-synthesis.

with:

> **Choose the mode first.** Fresh Exegesis (default — the full report, table below); **Claim Audit Mode** (Phase 0.5b — testing named claims from an overview or a new source); **Macro-Synthesis Mode** (Phase 0.5c — drawing together the cross-pericope arguments a completed set of dig-deeper runs jointly demonstrates); or **Synoptic Mode** (Phase 0.5d — one passage told twice in the canon, worked as a pair). The decision rules are at the end of each. If the ask is "is this claim/overview/source right?", it's a claim audit; if it's "what do all these runs add up to?", it's a macro-synthesis; **if the passage has a canonical twin and the differences between them are part of what is being asked, it is a synoptic run** — and a synoptic run is a modified Fresh Exegesis, not a separate report format.

**Edit 2** — `SKILL.md`, new section after Phase 0.5c and before the Adaptive Depth Principle:

> ### Phase 0.5d — Synoptic Mode (a modified Fresh Exegesis)
>
> Run this when the passage is told **twice** in the canon and the relation between the tellings is part of the question. It is not a separate report format: the sixteen tools, the extensions and the template all stand. What changes is the shape of the work.
>
> **1. Settle the direction of dependence before anything else, and never by default.** Three cases, and they are not interchangeable:
>
> | Case | Signal | How the run treats the pair |
> |---|---|---|
> | **Stated** | The later text names the earlier (Deut 5:12, 16 *"as the LORD your God commanded you"*) | Original and authorised re-issue. Differences are the later author's own application, and are read as homiletic moves |
> | **Open** | Neither text marks priority; canonical and compositional order may diverge (**Isa 36–39 ‖ 2 Kgs 18–20** — the case Phase 0.55 already names) | **Report both orders, resolve neither.** Differences are evidence in an unresolved question and may not be narrated as one text "editing" the other |
> | **Contested** | A scholarly hypothesis supplies the direction, the texts do not | Name the hypothesis as `[S]`, work the differences without it, and say what each direction would imply |
>
> **Getting this wrong is the mode's characteristic failure.** A run that assumes priority will describe a difference as a deliberate change, which is a claim about an author's intention that the "open" case cannot support.
>
> **2. Work in three movements.** Passage A in its own frame; passage B in its own frame; then the comparison. Do not average the two into a composite: **the harmonised text exists nowhere and is the mode's first pitfall.** Where one passage already has a completed solo dig, consume it at Phase 0.5 rather than re-working it, and say so in the scope note.
>
> **3. Run Phase 0.6 twice.** Each passage's positional necessity is a fact about its own book and cannot be inherited from its twin.
>
> **4. Diff mechanically before reading either text closely.** Align the passages verse by verse and compare the originals with accents, maqqef and paseq normalised (Amendment J). A mechanical diff is reproducible, catches what the eye slides over, and — crucially — **establishes what is identical**, which is as much a finding as what differs. Report the count of unchanged material explicitly.
>
> **5. Expect the Triad to behave differently.** Where the source is inside the same corpus as the citing text (Deuteronomy quoting Exodus), Move 2 (book usage) and Move 4 (internal echo) largely coincide. Say so rather than filing a nil return for one of them.
>
> **6. Reconcile against *both* book-overviews, and report the asymmetry.** Two overviews are live and they are rarely equally mature. Where one is materially behind the other — older, pre-corpus, built on a sweep rather than on solo digs — **that gap is a finding for the Book-Overview Tensions section**, because the weaker overview will systematically lack whatever the run's original-language work produced.
>
> **7. File it where it belongs to neither passage.** A report spanning two books goes at the level above both — the Torah root, the corpus root — not in either book's folder, with a cross-reference from each. Filename per the two-passage convention below.
>
> **Choosing Synoptic Mode.** Use it when the user names both passages; when the user names one and asks about its twin; or when a passage in the table of known twins is brought for a full dig and the differences bear on the findings. **Do not** use it to compare thematically similar passages that are not textual twins — two accounts of a similar event are not a synoptic pair, and the mode's discipline (mechanical diff, direction of dependence) has nothing to work on.

> - **Synoptic:** When the passage is told twice in the canon and the differences are part of the question. Operates on **two passages at once**, where Fresh Exegesis and Claim Audit operate on one and Macro-Synthesis operates across completed runs.

## Amendment H — The apparatus-spread gate

### Problem

**The corpus cannot see its own witness base.** `_texts/hebrew-wlc/` is a single manuscript tradition — Leningrad — and the Logos BHS export is the same manuscript with an apparatus attached. For questions of *wording* this is not a limitation, because that is what BHS prints and what every English OT translates. But for a class of finding it is a serious one, and the skill currently has nothing to say about it.

The class is: **findings that rest on features of the apparatus rather than on the words.** The *parashoth* (פ and ס). The accentuation, including the Decalogue's double system. Ketiv/qere. The Masorah. These are printed in the corpus **without variants**, so a finding built on them looks *fully verified* from inside the corpus — it passes gate item (e3), it is mechanically reproducible, and it is wrong about its own scope.

That is exactly what happened. Headline Finding 1 of the Decalogue run — that the paragraph divisions give Deuteronomy ten units and Exodus nine — was published as a claim about "the Masoretic paragraphing". Keil & Delitzsch report the load-bearing setumah absent from **234 of Kennicott's 694 manuscripts**. The finding survives, narrowed to Leningrad, and is arguably more interesting for being narrowed. But **nothing in the run could have raised the question**, and it was corrected only because Patrick independently put the matter to Logos after delivery.

**This is not the three-way triage.** That governs Hebrew *against Greek*. This governs variation *within* the Hebrew, in a layer the corpus does not represent at all. The two are easy to confuse and should be kept apart in the file.

Three further apparatus-features are already flagged as open questions in the Decalogue report and have the same shape: the setumah at Deut 5:10 (present in the WLC, not shown in the BHS export); the double accentuation; and the ketiv/qere at Deut 5:10.

### File and anchor

**Edit 1** — `SKILL.md`, Phase 10.5 (the hard gate). Insert a new item after (e3):

> (e4) **Apparatus-spread check.** Where a finding rests on a feature of the **apparatus** rather than on the wording — *parashoth* (petuchah/setumah), accentuation, ketiv/qere, Masorah, sigla — the corpus is a **single manuscript tradition** and cannot show how widely that feature is attested. The corpus establishes *that Leningrad has it*; it can never establish *that the Hebrew has it*. So: name the witness rather than the tradition ("in Leningrad", "as BHS prints it", never "the Masoretic text" unqualified); state that the feature is a reading tradition and not authorial where that is the case; and, before the finding enters a book overview or a sermon, **run one library pass on the manuscript spread**. Where that pass has not been run, tag the finding `[unchecked — apparatus spread]`, cap it at moderate confidence, and bar it from an overview on the same terms as an unverified chain. **A verified count and an unrepresentative witness look identical from inside the corpus.**

**Edit 2** — `SKILL.md`, Text-First Declaration block. Add a line after "**Chains verified:**":

> **Apparatus findings:** [n findings resting on parashoth / accents / ketiv-qere / Masorah — witness named for each, spread checked or tagged — or "None"]

**Edit 3** — `references/extensions/textual-variants.md`, new section immediately after the three-way triage and before "Catalogue of NT variants". **Reference tree — out of reach of a `SKILL.md` proposal card; see Round 1's note.**

> ## The fourth category: variation inside the Hebrew
>
> The three-way triage governs divergence between the **Hebrew and the Greek**. It says nothing about divergence **within the Hebrew tradition**, and a corpus built on one manuscript will not raise the question by itself.
>
> Two layers, with different properties:
>
> **Consonantal and vocalic variants.** What BHS's apparatus is for. Reported under category 2 of the triage, on the usual terms.
>
> **Apparatus and reading-tradition features** — *parashoth*, accentuation, ketiv/qere, Masorah. These are **not** part of the text, they are **not** authorial, and they **vary between manuscripts far more than a single printed edition suggests.** They are nonetheless first-rate evidence, because they record how the text was read and divided in antiquity — often centuries before the Masoretes fixed the pointing. Handle them so:
>
> - **Name the witness, never the tradition.** "In Leningrad", "as BHS prints it" — not "the Masoretic text".
> - **Say they are not authorial.** The parashoth pre-date the Masoretic pointing (the Mishnah knows them; the Gemara ascribes them to Moses) but are not original to the text. They are evidence about reception, never about composition.
> - **Check the spread before the finding carries weight.** The paradigm: the setumah dividing the coveting commandment is absent from 234 of Kennicott's 694 manuscripts and from many printed editions (Keil & Delitzsch, *Commentary on the OT* 1:393–94). A finding resting on it is about Leningrad until a library pass says otherwise.
> - **Keep the systems apart.** Accentuation and parashoth are independent division systems that can disagree, and a query about one returns nothing about the other. The Decalogue is printed under *two* accent systems in *both* Exodus 20 and Deuteronomy 5 — the *taʿam ʿelyon* dividing by commandment, the *taʿam taḥton* by verse length — which is the Masoretes preserving two answers rather than choosing one.
> - **Warrant.** A marker in the manuscript is `[T]` *as a datum about the text as transmitted*. What it implies about how the material should be divided or counted is reception, and is `[S]` or `[I]`. The `[T]` boundary applies here exactly as it does to authorship and date.

**Edit 4** — `SKILL.md`, Phase 0.2 (Load the substrate). Add a sentence to the end:

> **And know what the corpus cannot show you.** It holds one Hebrew manuscript tradition, so it can verify wording, counts and chains, and it can never report how widely an apparatus feature — a paragraph marker, an accent system, a ketiv — is attested. See gate item (e4).

### Cost

One library query, and only for a finding that rests on the apparatus — which is a small minority of findings. The Decalogue run had exactly one. The real cost is remembering that the category exists, which is what (e4) is for.

## Amendment I — Research-tool answers are claims to test, not findings

### Problem

The skill's *Handling Tools That Need External Data* tells a run to point a cross-reference tool at a **systematic sweep** rather than only at targeted queries, and to tag the results `[S]` as checking-stage material. That is right and it works. But it says nothing about **what an AI research assistant characteristically gets wrong**, and the failure mode is specific enough to name.

**It reasons from the English version by default.** Asked how the Bible designates the Decalogue, Logos answered that the biblical texts *"consistently employ 'Ten Commandments' when naming this collection"*, citing the three verses that read עֲשֶׂרֶת הַדְּבָרִים. It had even quoted the Hebrew sense two paragraphs earlier and then reasoned from the NASB95's rendering anyway. **An English rendering was reported as the biblical text's own term.** For a project whose first discipline is that no English version is ever merely a translation, that is precisely the error the method exists to prevent — arriving with citations attached.

**It will answer from general knowledge when the library has nothing, and the flag is easy to miss.** The same session produced two answers on the section markers. The first, marked "from my general knowledge", defined a setumah as meaning *"there is no space break before the next verse"* — the opposite of the truth. The second, sourced from Hastings, was correct. Both looked equally authoritative in the reply.

The general shape: **a cited answer is not a verified answer, and the citation makes it feel like one.** The skill already treats a commentary this way. It should say the same of a research tool, in the section that tells the run to use one.

### File and anchor

**Edit 1** — `SKILL.md`, `## Handling Tools That Need External Data`. Add a fifth numbered point after point 4:

> 5. **Treat a research tool's answers as claims to test, exactly as you would a commentary's — and know its two characteristic errors.** A cited answer is not a verified answer, and the citation is what makes it feel like one.
>
>    **(a) It reasons from the English version by default.** Any answer about what "the text says", what a term "is", or how Scripture "refers to" something must be checked against the corpus before it is reported. *Worked example:* asked how the Bible designates the Decalogue, a Study Assistant answered that the biblical texts "consistently employ 'Ten Commandments'", citing Exod 34:28; Deut 4:13; 10:4 — the three verses whose Hebrew reads עֲשֶׂרֶת הַדְּבָרִים, "the ten words". The citations were right and the conclusion was an artefact of reading a rendering as the designation. **Where a tool's answer and the corpus disagree about wording, the corpus wins and the disagreement is itself worth reporting.**
>
>    **(b) It will answer from general knowledge when the library has nothing.** Such answers usually carry a disclaimer, and the disclaimer is easy to miss beside a well-cited paragraph in the same reply. **Check every claim for a source before relying on it**, and downgrade an uncited claim to the same standing as Claude's own recall — which is to say, flag it and verify it.
>
>    Where a tool's answer **corrects** the run, say so at the point of use and rewrite the finding around it rather than appending a caveat. Where the run **corrects the tool**, argue it from the text rather than asserting it. Both are reportable; neither is embarrassing.

### Cost

None to the workflow — it hardens an existing instruction. The only cost is a slower reading of research-tool output, which is where the time should go.

## Amendment J — Search normalisation, completed

### Problem

The rule learned 8 September — **always search accent-insensitively**, NFD-decompose and strip combining marks — is right and is already in the corpus documentation. It is also **incomplete**, and the gap fails silently in the same way the accent problem did.

**Maqqef (־) and paseq (׀) are not combining marks.** NFD-stripping leaves them in place, so they survive into the normalised string and defeat any pattern that expects whitespace between words. Two live examples from the Decalogue run:

- `פנים\s+בפנים` returned **nil** against Deut 5:4, which contains the phrase — because the Hebrew has a paseq between the words: פָּנִ֣ים ׀ בְּפָנִ֗ים.
- `פנים\s+אל[- ]פנים` returned **nil** across the whole WLC — because אֶל־פָּנִים is bound by maqqef, and the pattern's hyphen is not the maqqef character.

Both were nil returns on texts that contain the phrase, which is the worst kind of failure: it looks exactly like a genuine finding of absence. Corrected, the same searches return the result that became a headline finding — **פָּנִים בְּפָנִים occurs once in the Hebrew Bible; פָּנִים אֶל־פָּנִים five times.**

The fix is one line in the normaliser: replace ־ and ׀ with spaces before collapsing whitespace.

### File and anchor

**Edit 1** — `SKILL.md`, Phase 10.5, gate item (e3). Extend the parenthetical on searching. After "*by lemma, never by pointed surface form or English gloss*" add:

> — and where a **phrase** search is unavoidable, normalise **maqqef (־) and paseq (׀) to spaces** as well as NFD-stripping combining marks, since neither is a combining mark and both defeat a whitespace pattern silently, returning a nil on a text that contains the phrase

**Edit 2** — `references/04-words-and-translations.md`, Tool 7 operational guidance, the "Verify before you report" bullet added by Amendment C. **Reference tree — out of reach of a proposal card.** Add at the end:

> A **phrase** search needs one step more than a word search. Maqqef and paseq are not combining marks, so accent-stripping leaves them standing between the very words your pattern is trying to match: normalise ־ and ׀ to spaces before matching. Two searches in the Decalogue run returned nil on texts that contained the phrase for exactly this reason, and a nil return is indistinguishable from a real absence.

**Edit 3** — `_texts/README.md`, the "Using it" section. **Not a skill file** — Patrick's corpus documentation, listed here so the record is complete. Extend the existing accent-insensitivity note:

> **Surface phrase searches need maqqef and paseq normalised too.** Stripping accents is not enough: ־ and ׀ are not combining marks and will sit between the words a pattern is trying to match. Normalise both to spaces first. `find.py` lemma searches are unaffected.

### Cost

One line of code in any ad-hoc search, and it makes two known silent failures impossible.

## What is deliberately not proposed

**A synoptic re-run of the pairs already partly covered.** Isaiah 36–39 and 2 Kings 18–20 both have material in the folder, and it would be tempting to run the pair immediately as a test of Amendment G. The honest sequence is the other way round: adopt the amendment, then run the pair *under* it, so the mode is tested rather than retrofitted. The Decalogue report is the specimen; Isaiah/Kings should be the first true trial, not a second specimen.

**Any rule about how many manuscripts a finding needs.** Amendment H asks for the spread to be *checked and stated*, not for a threshold. A feature attested in one manuscript can be the right reading and a feature in six hundred can be a harmonisation; the skill's job is to make the run say which manuscripts it is talking about, not to arithmetise the answer.

**A general "consult the library" step.** Amendment I hardens the existing instruction rather than adding a phase. A blanket requirement to run library queries would compete with the text-first discipline, which is the one thing in this method that must not be diluted: the corpus is the substrate, and the library is a check on it.

**Anything about the Deuteronomy overview.** That it is v0.1.0, ESV and pre-corpus is a fact about a document, not about the skill, and it belongs in the run note and the Book-Overview Tensions section where it already stands.
